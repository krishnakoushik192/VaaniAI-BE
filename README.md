# vanni-backend

TypeScript + Express + MongoDB API for the Vanni AI app. It stores shopkeepers and their customers, records bills and dues payments, and keeps the shop totals (today's bill, weekly bill, dues).

All money is stored as **integer paise** (₹1 = 100). This matches `VanniAi/src/logic/money.ts`.

## Database design

Two collections: `shopkeepers` and `customers`. Each customer has a `shopkeeperId` that points to its shop.

**shopkeepers**

| Field | Type | Notes |
|---|---|---|
| `_id` | ObjectId | |
| `shopName` | string | |
| `shopkeeperName` | string | |
| `mobileNumber` | string | unique, 10 digits; used for login |
| `passcodeHash` | string | bcrypt hash of a 4–6 digit passcode. The plain passcode is never stored |
| `upiId`, `language` | string | optional; the app's profile screen uses them |
| `weeklyBill` | paise | sum of all bills this week (Mon–Sun, India time) |
| `todaysBill` | paise | sum of all bills today |
| `duesTotal` | paise | what all customers owe right now |
| `todaysDues` | paise | new credit (khata) given today |

**customers**

| Field | Type | Notes |
|---|---|---|
| `_id` | ObjectId | |
| `shopkeeperId` | ObjectId → shopkeepers | indexed |
| `customerName` | string | |
| `phoneNumber` | string | optional; unique within a shop |
| `isWalkinCustomer` | boolean | each shop gets one shared "Walk-in" customer for anonymous cash/UPI sales |
| `pastDues` | paise | what this customer owes |
| `dueSince` | date | when the current unpaid balance started |
| `recentTransactions` | array | **last 3 only**: `{ txnId, kind: bill/payment, method: cash/upi/khata, amount, items, discount, billNo, createdAt }` |

How the totals update:

- A bill adds its amount to `todaysBill` and `weeklyBill`. A khata (credit) bill also adds it to the customer's `pastDues`, `todaysDues` and `duesTotal`.
- A payment subtracts from `pastDues` and `duesTotal`.
- `todaysBill` and `todaysDues` reset when the India-time day changes. `weeklyBill` resets on Monday.
- The customer and the shop are updated in one MongoDB transaction, so they can't disagree.
- The server computes the bill total from the items (`qty × rate − discount`). It never accepts a total from the app or from an LLM.

> Limitation: only the last 3 transactions per customer are kept. If you later need a full history screen, monthly reports or bill reprints, add a third `transactions` collection.

## API

All routes except `/auth/*` need the header `Authorization: Bearer <token>`.

| Method | Path | Body |
|---|---|---|
| POST | `/api/auth/register` | `{ shopName, shopkeeperName, mobileNumber, passcode }` → `{ token, shopkeeper }` |
| POST | `/api/auth/login` | `{ mobileNumber, passcode }` → `{ token, shopkeeper }` (5 wrong tries → locked for 15 min) |
| GET / PATCH | `/api/shopkeeper/me` | profile + totals / `{ shopName?, shopkeeperName?, upiId?, language? }` |
| GET | `/api/customers?search=` | list, highest dues first |
| POST | `/api/customers` | `{ customerName, phoneNumber?, openingDue? }` |
| GET / PATCH / DELETE | `/api/customers/:id` | delete only works when dues are 0 |
| POST | `/api/transactions` | bill: `{ kind:"bill", txnId, customerId?, method:"cash"/"upi"/"khata", items:[{name,qty,unit,rate}], discount?, billNo? }`<br>payment: `{ kind:"payment", txnId, customerId, method:"cash"/"upi", amount }` |
| POST | `/api/voice/bill` | form-data `audio` (≤30 s), `customerId?`, `languages?` → `{ transcript, draft }`. **Does not save** |
| POST | `/api/voice/extract` | `{ transcript, customerId? }` → `{ draft }` (same as above, from text) |
| POST | `/api/voice/transcribe` | form-data `audio` → `{ transcript, detectedLanguage }` |
| GET | `/api/health` | no auth |

**Voice flow:** audio → Gnani STT (Prisma v3.0, using the shop's customer names as key terms) → Gemini (`gemini-3.5-flash-lite`, JSON schema) reads customer, items, qty, unit, prices and payment method → `src/lib/billDraft.ts` computes every amount in paise and flags lines that need checking → the app shows the draft → the shopkeeper confirms → the app saves it with `POST /api/transactions`.

See **[TESTING.md](TESTING.md)** for how to test every API by hand.

`txnId` is generated by the app (`clientId()` in `money.ts`). Sending the same one twice (a retry) does not record the transaction twice.

## 1. Create the MongoDB database (Atlas + Compass)

Vercel runs in the cloud and can't reach a MongoDB on your laptop, so use **MongoDB Atlas** (free M0 tier). Use Compass to look at the data.

1. Sign up at https://cloud.mongodb.com and create a **Project** named "Vanni AI".
2. **Create a cluster** → choose **M0 (Free)**, provider AWS, region **Mumbai (ap-south-1)** (closest to your users).
3. **Database Access** → *Add New Database User* → username `vanni-app`, *Autogenerate Secure Password* → copy the password somewhere safe → role *Read and write to any database*.
4. **Network Access** → *Add IP Address* → **Allow access from anywhere (`0.0.0.0/0`)**. Vercel has no fixed IP addresses, so this is required. The database user's password is what protects the database.
5. **Clusters → Connect → Drivers** → copy the connection string:
   `mongodb+srv://vanni-app:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`
   Replace `<password>` with the real password. If the password contains `@ : / ? #`, URL-encode it or generate a new password with only letters and digits.
6. **Compass**: open MongoDB Compass → *Add new connection* → paste the same string → *Save & Connect*. The `vanni` database appears once the backend writes its first record. You don't need to create the collections by hand: the app creates `shopkeepers`, `customers` and their indexes automatically.

## 2. Run the backend locally

```bash
cd vanni-backend
npm install
cp .env.example .env      # then edit .env: MONGODB_URI and JWT_SECRET
npm run dev               # http://localhost:4000
```

Generate a `JWT_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Test it:

```bash
curl -X POST http://localhost:4000/api/auth/register -H "content-type: application/json" -d "{\"shopName\":\"My Shop\",\"shopkeeperName\":\"Me\",\"mobileNumber\":\"9000000001\",\"passcode\":\"1234\"}"
```

The new shopkeeper then shows up in Compass under `vanni → shopkeepers`.

`npm run smoke` runs an end-to-end test against a temporary in-memory MongoDB. It doesn't need Atlas.

| Script | What it does |
|---|---|
| `npm run dev` | runs `src/*.ts` directly with tsx, restarts on save |
| `npm run typecheck` | type-checks without writing files |
| `npm run build` | compiles to `dist/` |
| `npm start` | runs the compiled `dist/index.js` (after `npm run build`) |
| `npm run smoke` | end-to-end test on an in-memory MongoDB |

> From the Android emulator, `localhost` is the emulator itself. Use `http://10.0.2.2:4000` instead. From a real phone, use your PC's Wi-Fi IP (e.g. `http://192.168.1.5:4000`).
